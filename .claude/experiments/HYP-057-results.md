> Гипотеза: `myRep/_project-hub/hypotheses/HYP-057-deterministic-concurrency-testing-swift.md`
> Полигон: VK Long Poll + `CommandProcessor` (release/v0.5.0). Linux, Swift 6.4, ubuntu-home.

## Эксперимент 2 — ложно-зелёный от сериализации (falsifiable)

Тест «две задачи одновременно → ровно одна проходит», 50 прогонов на каждую клетку.
Мутант = убранная защита. Сериализация = `withMainSerialExecutor` (swift-concurrency-extras 1.4.1).

| Гонка | Защита | Обычный запуск | `withMainSerialExecutor` |
|---|---|---|---|
| **2a. Реентерабельность actor на `await`** (`CommandProcessor.isBusy`) | есть | 50/50 ✅ | 50/50 ✅ |
| | **нет (мутант)** | 50/50 ❌ (ловит) | **50/50 ❌ (ловит)** |
| **2b. Гонка данных без `await`** (check-then-act, `NSLock`) | есть | 50/50 ✅ | 50/50 ✅ |
| | **нет (мутант)** | 50/50 ❌ (ловит) | **50/50 ✅ — ложно-зелёный** |

**Вывод — гипотеза подтверждена с уточнением границы:**
- Сериализация **прячет** гонки, которым нужна настоящая параллельность потоков (гонки данных, check-then-act без точек приостановки) — 2b.
- Сериализация **не прячет** логические гонки на точках `await` (actor reentrancy): последовательный исполнитель всё равно переключает задачи на `await`, гонка становится воспроизводимой — 2a.
- Правило: `withMainSerialExecutor` допустим для тестов порядка событий/реентерабельности; для thread-safety контрактов (замки, `@unchecked Sendable`) — **только** обычный параллельный запуск (+ TSan, повторы).

**Дополнительно:** для 2a лучший инструмент оказался вообще без библиотеки — «шпион и затвор»
(`GatedHTTPClient` в `CommandProcessorConcurrencyTests`): детерминированно, мутант убит 20/20, исходный код 20/20.
Библиотека в проекте не оставлена (удалена следующим коммитом после эксперимента).

## Эксперимент 3 — цена инъекции времени

Ось «время» в цикле VK Long Poll: повтор после сетевой ошибки с паузой 1 → 2 → 4 … 60 c.

- Внедрено **функцией** `sleep: @Sendable (Duration) async throws -> Void` (default `Task.sleep`), не протоколом `Clock`.
- Цена: **1 параметр в 1 файле** (`VKLongPollClient`), в тестах — `SleepRecorder` 12 строк. swift-clocks не нужен.
- Критерий отказа гипотезы (invasive refactor за пределы модуля) **не достигнут** → инъекция времени окупается.
- Наблюдение: для одного места «функция-пауза» дешевле `Clock`; `Clock` нужен, когда в коде есть дедлайны/`now`, а не только `sleep`.

## Диагностика retain-циклов Swift 6.4

Новое предупреждение (`'weak' ownership of capture 'self' differs from implicitly-captured strong reference in outer scope`)
на всём tg-client — **0 срабатываний**, включая новый цикл Long Poll: замыкание захватывает `processor`, не `self`;
`[weak self]` в коде всего два, оба без вложенности. Флаг не нужен — включено по умолчанию.

## Побочные находки (не про гипотезу, но из тех же тестов)

- Тест повторов **поймал настоящий баг**: после сетевой ошибки `VKLongPollClient` терял сессию и перезапрашивал сервер.
- Бесконечный цикл в тесте без лимита = вечный прогон: на suite `.timeLimit(.minutes(1))` — зависание становится провалом (открытый вопрос 2 гипотезы: «таймауты как контракт»).
- Swift 6.4 / SwiftPM на Linux: инкрементальная сборка однажды слинковала устаревший символ из кэша компиляции — помогла только чистая сборка.
