# Get Summary

Одной командой собрать непрочитанное из Telegram и вернуть его как **структурированные данные** для агента.
Пометка прочитанным — **отдельным явным шагом** после того, как сводка доставлена. Два шага асинхронны:
`get-summary` отдал JSON и вышел, `read` вызывается позже (пауза может быть любой).

## User Story

Как агент (или пользователь через агента), я хочу одной командой получить все непрочитанные сообщения
сгруппированные по чатам (от кого = название чата/канала), чтобы составить сводку — **не открывая Telegram руками**.
Помечать прочитанным — только то, что было в доставленной сводке, и только по явной команде.

**Данные, а не готовый текст:** сводку формирует агент (его работа над JSON). `get-summary` возвращает материал,
не AI-текст. Старый путь через OpenAI (<doc:GenerateSummary>) — отдельно, в этот сценарий не входит.

**Пометка отдельным шагом:** «пометить только доставленное» требует, чтобы доставка сначала прошла. Разведение
`get-summary` (чтение) и `read` (изменение) не теряет сообщения, если агент упал между «собрал» и «доставил».

**Курсор решает проблему паузы:** `read` метит прочитанным только до `last_message_id` на чат, собранного в сводке.
Что прилетело за время паузы — остаётся непрочитанным и попадёт в следующий `get-summary`. Длина паузы не важна.

## Предусловия

- Служба `tg-client service` запущена: она единственный владелец сессии TDLib и слушает unix-сокет
  `${TG_SOCKET:-$TDLIB_STATE_DIR/tg-client.sock}` (права 0600). CLI сам TDLib не открывает.
- Непрочитанные чаты — через существующий `ChannelMessageSource.fetchUnreadChats()` / `fetchMessages()`

## Протокол сокета

Одно соединение — один запрос (JSON-строка) и один ответ (JSON до EOF). Запросы служба выполняет по одному.

```json
→ {"op":"get-summary"}
→ {"op":"read","cursor":[{"chat_id":-100...,"up_to_message_id":105}]}
← {"ok":true,"result":{...}}
← {"ok":false,"error":{"error_type":"permission_denied","field":"op","message":"..."}}
```

Разрешены только R0 `get-summary` и R1 `read`; любой другой `op` — `permission_denied`.

## Контракт CLI

Код выхода: `0` ok · `2` неверный ввод (`schema_validation`/`parse_error`) · `3` запрещено (`permission_denied`) ·
`11` служба не отвечает (нет сокета) · `12` прочий сбой службы/TDLib. Ошибка — первой строкой stderr, однострочный
JSON `{"error_type","field","message","hint"}`.

## Шаги

1. **`tg-client get-summary`** — собрать непрочитанное, вернуть JSON в stdout, записать курсор в файл, выйти.
   **Состояние VK/TG не меняется** (не помечает прочитанным).
   ```json
   { "collected_at": "2026-10-15T...Z",
     "chats": [
       { "chat_id": -100..., "title": "...", "kind": "channel|group|dm", "unread_count": 5,
         "messages": [ { "message_id": 101, "text": "..." } ],
         "last_message_id": 105 } ],
     "cursor": [ { "chat_id": -100..., "up_to_message_id": 105 } ] }
   ```
   Курсор дублируется в файл по умолчанию `${TG_CURSOR_FILE:-$TDLIB_STATE_DIR/last-cursor.json}`.

   **Форум (чат с темами):** у каждой темы своя граница прочитанного, чатовый `unread_count` = сумма тем и
   обновляется с задержкой. Поэтому сбор идёт по темам с непрочитанным (`getForumTopics` → `getForumTopicHistory`),
   берутся сообщения новее `last_read` темы; у сообщения есть `"topic": {"id": 7, "name": "Sharing"}`; курсор —
   запись на тему `{"chat_id": …, "forum_topic_id": 7, "up_to_message_id": …}`. Форум без тем с непрочитанным
   в сводку не попадает (даже если чатовый счётчик ещё не обнулился).

2. **Агент формирует сводку** из JSON (вне tg-client) и доставляет её владельцу.

3. **`tg-client read`** (без аргументов) — пометить прочитанными чаты из курсора в файле по умолчанию.
   Override: `read --input-json <file>` с `{"cursor":[…]}` (схема `schemas/wrapper-read-input.v1.json`, курсор несёт
   агент); `--cursor <file>` с голым массивом — совместимость. **Меняет состояние** (`viewMessages` до `up_to_message_id`).
   Частичный отказ по одному чату не валит остальные (как в `MarkAsReadService`).
   Запись темы форума метится `viewMessages(up_to, source=messageSourceForumTopicHistory)` — ровно эта тема.

## Критерии приёмки

| # | Given | When | Then |
|---|---|---|---|
| AC-1 | есть непрочитанные | `get-summary` | JSON по схеме; у чата `title`, `kind`, `unread_count`, `last_message_id`; у сообщений `message_id` + `text`; `cursor` непустой |
| AC-2 | непрочитанных нет | `get-summary` | `{"chats": [], "cursor": []}`, код 0, файл курсора — пустой список |
| AC-3 | после `get-summary` | повторный `get-summary` | те же чаты (сбор **не пометил** прочитанным) |
| AC-4 | курсор в файле | `read` без аргументов | чаты помечены до `up_to_message_id`; следующий `get-summary` их не содержит |
| AC-5 | курсор из файла/`--cursor` | — | `read` метит ровно до `up_to_message_id`, не трогая сообщения, пришедшие после сбора |
| AC-6 | один чат недоступен | `read` по нескольким | остальные помечены, в ответе per-chat результат, код 0 |
| AC-7 | любой вывод | — | stdout — только JSON; никаких интерактивных промптов; ошибки/логи — в stderr |
| AC-8 | служба работает (мост VK) | `get-summary`/`read` | ответ через сокет, служба не останавливается |
| AC-9 | служба не запущена | `get-summary` | код 11, `upstream_failure` + `hint` в stderr |
| AC-10 | запрос в сокет с `op` вне R0/R1 | — | `permission_denied`, TDLib не трогается |
| AC-11 | форум с непрочитанным в темах | `get-summary` → `read` | сообщения с `topic`, курсор на тему; после `read` у тем непрочитанного нет, форума нет в следующей сводке |

## Тесты

- **E2E (реальный клиент — владелец):** при работающей службе `get-summary` → форма + чат остался непрочитанным → `read` → повторный `get-summary` его не содержит. Вручную (2026-10-15: 5 чатов за 5 с, служба не останавливалась; `op=send` → отказ; 2026-10-16: форум Podlodka AI Crew — 4 темы помечены `read --input-json` только с записями форума, остальные 9 чатов не тронуты).
- **Component (моки, TDD):** `BrokerTests` (`MockTDLibFFI`) — протокол сокета, R0/R1, отказы; `CursorApplyTests`, `SummaryCollectorTests`.
- **Unit:** `UnixSocketTests` — запрос/ответ, права 0600, замена оставшегося сокета, отказ при недоступной службе.
