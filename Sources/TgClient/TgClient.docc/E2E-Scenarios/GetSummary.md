# Get Summary

Одной командой собрать непрочитанное из Telegram и вернуть его как **структурированные данные** для агента.
Пометка прочитанным — **отдельным явным шагом** после того, как сводка доставлена. Два шага асинхронны:
`get-summary` отдал JSON и вышел, `read` вызывается позже (пауза может быть любой).

## User Story

Как агент (или пользователь через агента), я хочу одной командой получить все непрочитанные сообщения
с контекстом «от кого, в каком чате, про что», чтобы составить сводку — **не открывая Telegram руками**.
Помечать прочитанным — только то, что было в доставленной сводке, и только по явной команде.

**Данные, а не готовый текст:** сводку формирует агент (его работа над JSON). `get-summary` возвращает материал,
не AI-текст. Старый путь через OpenAI (<doc:GenerateSummary>) — отдельно, в этот сценарий не входит.

**Пометка отдельным шагом:** «пометить только доставленное» требует, чтобы доставка сначала прошла. Разведение
`get-summary` (чтение) и `read` (изменение) не теряет сообщения, если агент упал между «собрал» и «доставил».

**Курсор решает проблему паузы:** `read` метит прочитанным только до `last_message_id` на чат, собранного в сводке.
Что прилетело за время паузы — остаётся непрочитанным и попадёт в следующий `get-summary`. Длина паузы не важна.

## Предусловия

- TDLib авторизован (сессия в `TDLIB_STATE_DIR`), при необходимости `TDLIB_PROXY`
- Непрочитанные чаты — через существующий `ChannelMessageSource.fetchUnreadChats()` / `fetchMessages()`

## Шаги

1. **`tg-client get-summary`** — собрать непрочитанное, вернуть JSON в stdout, записать курсор в файл, выйти.
   **Состояние VK/TG не меняется** (не помечает прочитанным).
   ```json
   { "collected_at": "2026-10-15T...Z",
     "chats": [
       { "chat_id": -100..., "title": "...", "kind": "channel|group|dm", "unread_count": 5,
         "messages": [ { "message_id": 101, "from_name": "...", "date": "...Z",
                         "text": "...", "attachments": ["photo"], "reply_to": {"from_name":"...","text":"..."} } ],
         "last_message_id": 105 } ],
     "cursor": [ { "chat_id": -100..., "up_to_message_id": 105 } ] }
   ```
   Курсор дублируется в файл по умолчанию `${TG_CURSOR_FILE:-$TDLIB_STATE_DIR/last-cursor.json}`.

2. **Агент формирует сводку** из JSON (вне tg-client) и доставляет её владельцу.

3. **`tg-client read`** (без аргументов) — пометить прочитанными чаты из курсора в файле по умолчанию.
   Override: `read --cursor <file>` (курсор несёт агент). **Меняет состояние** (`viewMessages` до `up_to_message_id`).
   Частичный отказ по одному чату не валит остальные (как в `MarkAsReadService`).

## Критерии приёмки

| # | Given | When | Then |
|---|---|---|---|
| AC-1 | есть непрочитанные | `get-summary` | JSON по схеме; у чата `kind`, `unread_count`, `last_message_id`; у сообщений `from_name`, `text`/`attachments`; `cursor` непустой |
| AC-2 | непрочитанных нет | `get-summary` | `{"chats": [], "cursor": []}`, код 0, файл курсора — пустой список |
| AC-3 | после `get-summary` | повторный `get-summary` | те же чаты (сбор **не пометил** прочитанным) |
| AC-4 | курсор в файле | `read` без аргументов | чаты помечены до `up_to_message_id`; следующий `get-summary` их не содержит |
| AC-5 | курсор из файла/`--cursor` | — | `read` метит ровно до `up_to_message_id`, не трогая сообщения, пришедшие после сбора |
| AC-6 | один чат недоступен | `read` по нескольким | остальные помечены, в ответе per-chat результат, код 0 |
| AC-7 | любой вывод | — | stdout — только JSON; никаких интерактивных промптов; ошибки/логи — в stderr |

## Тесты

- **E2E (реальный клиент — владелец):** `get-summary` → форма + чат остался непрочитанным → `read` → повторный `get-summary` его не содержит. Вручную (нужен авторизованный TDLib).
- **Component (моки, TDD):** `MockTDLibFFI` — сбор возвращает N чатов с `last_message_id`; `read` метит нужный диапазон; частичный отказ; курсор читается из файла и из `--cursor`.
- **Unit:** сборка JSON-ответа и курсора из доменных моделей; разбор файла курсора / `--cursor`.

## Вне scope

- CLI-обвязка целиком (контракт команд, коды выхода) — **следующая** история.
- `send` (отправка) и whitelist адресатов — позже, после безопасных команд.
- AI-текст сводки через OpenAI — отдельный путь <doc:GenerateSummary>.
- Инкрементальный дифф «что прилетело за паузу» (сверка со старым курсором) — см. BACKLOG, не здесь.
