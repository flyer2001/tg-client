# VK Bridge

Управление Telegram-клиентом через личное VK-сообщество, когда сам Telegram недоступен (блокировки мобильного интернета).

## User Story

Как владелец, когда Telegram заблокирован, а VK работает, я хочу командами в своём VK-сообществе
получить список непрочитанных чатов, прочитать нужные, ответить и пометить прочитанным,
чтобы не терять переписку в Telegram.

**Транспорт v0.5.0:** VK **Bots Long Poll** — клиент сам держит исходящий запрос к VK.
Не нужны публичный домен, HTTPS, nginx и открытый порт (в отличие от webhook spike).

**Доступ:** только `VK_BOT_OWNER_IDS`. Сообщения остальных игнорируются молча (в логе — `deny from_id=…`).

## Команды и критерии приёмки

| # | Команда | Given | Then |
|---|---------|-------|------|
| US-1 | `/test` (`test`, `тест`, `ping`) | сервис запущен, TDLib авторизован | ответ о статусе: TDLib подключён, кто владелец |
| US-2 | `/digest` | есть непрочитанные каналы / группы / ЛС | меню с номерами, сгруппированное по типам; архив не попадает; длинное меню — чанками ≤ 4096 символов |
| US-2 | `/digest` | непрочитанных нет | `📭 Непрочитанных нет.` |
| US-3 | `/get N`, `/get all`, `/get channels\|groups\|dm` | меню построено | текст непрочитанных выбранных чатов (подписи медиа — тоже), чанками |
| US-3 | `/get N` | меню не строилось | `ℹ️ Сначала вызови /digest…` |
| US-3 | `/get 99` | в меню меньше чатов | `🤷 Номер 99 не найден в последнем меню.` |
| US-4 | `/last N [count]` | меню построено | последние `count` сообщений чата (включая прочитанные), oldest → newest |
| US-5 | `/reply N текст` | меню построено | текст ушёл в чат #N от имени владельца, подтверждение `✅ Ушло в Telegram → …` |
| US-6 | `/to username текст` | @username существует | `searchPublicChat` → `sendMessage`, подтверждение; `@` в начале не важен |
| US-6 | `/to nobody текст` | username не найден | `❌ Не нашёл @nobody: …` |
| US-7 | `/read N` | меню построено | чат #N помечен прочитанным (`viewMessages`, `forceRead`), `✅ '…' помечен прочитанным.` |
| — | любая команда | предыдущая ещё выполняется | `⚠️ Уже обрабатываю предыдущую команду, подожди.` |
| — | неизвестная команда | — | подсказка со списком команд |

## Long Poll: критерии надёжности

| Ситуация (ответ VK) | Ожидаемое поведение |
|---------------------|---------------------|
| `failed: 1` — история событий устарела | взять новый `ts` из ответа, продолжить |
| `failed: 2` — истёк `key` | перезапросить `groups.getLongPollServer`, продолжить |
| `failed: 3` — потеряна информация | перезапросить server + key + ts |
| сетевая ошибка / таймаут | повтор с растущей задержкой, без падения сервиса |
| остановка сервиса (SIGTERM) | текущий запрос отменяется, цикл завершается без утечек |

## Предусловия

- ✅ VK-сообщество: сообщения и «Возможности ботов» включены, Long Poll API включён (версия 5.199, событие «Входящее сообщение»)
- ✅ Ключ сообщества с правами «управление сообществом» + «сообщения сообщества»
- ✅ Владелец хотя бы раз написал сообществу (иначе VK не даст боту ответить)
- ✅ TDLib авторизован (один раз `swift run tg-client` интерактивно)
- ✅ `.env`: `VK_BOT_TOKEN`, `VK_BOT_GROUP_ID`, `VK_BOT_OWNER_IDS`

## Как проверить сценарий

1. Запустить сервис: `swift run tg-client service`
2. В VK-сообществе отправить `/test` → ответ о статусе
3. `/digest` → меню; `/get 1` → текст; `/read 1` → чат прочитан (проверить в Telegram, что галка снялась)
4. Остановить сервис `Ctrl+C` → процесс завершается сразу, без зависшего запроса
